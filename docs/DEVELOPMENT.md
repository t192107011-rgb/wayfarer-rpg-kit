# 动作模板扩展指南

## 当前架构

`ActionGame` 是纯 Java 实时规则，时间单位为秒、空间单位为世界像素。`WorldView` 将触控转换为输入，在 Choreographer 帧回调里按 1/60 秒推进模拟；单次最多补五步，后台恢复不补算离线时间。所有状态在主线程更新，保存与模拟不会并发修改。

显示坐标固定为 960×540，在实际屏幕等比缩放并留边；触点先减去留边再除以缩放。主 Activity 横屏显示，并处理刘海、系统栏安全区。左摇杆和攻击使用不同 pointer ID，抬起其中一根手指只清除对应输入；取消触摸、失焦、暂停均清空输入。

渲染、美术和音效可独立替换。玩法规则不应读取 Canvas、Activity 或文件系统。新增特性先定义规则与保存字段，再连接界面。

## 调整角色和战斗

角色基础属性、普攻间隔、技能在 `ActionGame` 中集中定义。三个基础角色在一次远征开始前选择，当前没有战斗内切换角色。

- 近战：攻击前摇后进入有效窗口，使用攻击弧、距离和视线检查；每次挥击的命中集合防止同一敌人逐帧重复受伤。
- 远程：弹丸按速度运动，用上一帧到当前帧的线段检测命中，防止高速箭穿过目标。
- 闪避：位移期间仍做墙体碰撞；单独的短暂无敌计时和冷却，不允许穿墙。
- 技能：剑士/双刃是圆形范围效果，当前允许穿过薄障碍；普通近战和弓箭受掩体阻挡。若希望技能也受掩体阻挡，在技能目标筛选中补 `lineClear`。
- 敌人：接近 → 明确预警 → 攻击/冲锋 → 恢复。攻击预警锁定方向，避免出手前突然追踪导致无法躲避。
- 首领：圆形重击和环形弹幕，半血后增加弹丸数量。大范围技能必须同步修改预警半径与真实判定。

新角色建议将数值和技能映射提取成定义表；不要让新增 ID 改变已有角色存档的含义。当前代码为易读的小型演示实现，大规模内容应进一步拆分角色、技能、房间和敌人定义。

## 生成关卡

当前五个关卡共用 1120×760 的房间范围，障碍和普通敌群按保存的随机状态生成。中央通路、上下出生区与两处出口始终留空。当前没有随机连接多个房间的地图，也没有真正分叉的世界路线；左右出口改变奖励，下一阶段仍按顺序推进。

若要扩展为完整地牢：先生成房间图与门连接，再填充各房间；检查出生点到出口可达、敌人生成点合法、事件唯一、门两端对应，最后验证所有关卡。将房间 ID、访问状态、已清场标记加入快照，回访房间不得重发奖励。

敌人目前是直接追踪、轴向碰撞滑动和受阻时绕近侧障碍。复杂迷宫需替换为导航网格或周期性 A* 寻路；不要在每个绘制帧为每个敌人跑全图搜索。

## 局内与永久成长

`damageBonus`、`healthBonus`、`speedBonus` 为本轮增益，回营地或开始新远征时清零。`bank`、`power`、`vitality`、三角色 `experience` 为永久状态。结算通过 Mode 门禁防止重复领取；恢复结算画面不能再次发奖励。

奖励加成应同时更新状态和领取标记。物品/天赋系统应使用稳定 ID，给每类数量和等级设上限。重开远征不等于删除档案；档案重置需要确认，并保留三个手动槽。

## 存档与兼容

动作版使用 `wayfarer-action` v1 协议与 `action-saves-v1` 私有目录，保存当前关卡、玩家状态、敌人状态、弹丸、掉落、冷却、随机种子和营地数据。旧回合制 `wayfarer-rpg` 协议不兼容，使用独立 applicationId 并存，旧存档不动。

1. 所有输入字节限定在 128 KiB；数组数量、数值上下限、有限浮点、地图位置与模式关系都要验证。
2. 先恢复到新对象，校验成功后再替换运行中的游戏。
3. 保存使用 AtomicFile，读写失败提示且不静默重置。
4. 正在进行的近战挥击在恢复时取消，保留剩余攻击冷却，避免重播命中。弹丸和敌人预警则按快照恢复。
5. 读档后切为暂停，玩家点击继续才开始战斗。
6. 增加字段或改语义必须升协议版本并显式迁移；本地校验是稳定性措施，不是反作弊。

当前每 15 秒、房间/模式切换、暂停及切后台保存。被系统瞬间杀进程时最多可能丢失自动快照间隔内的进度。保存失败不会虚报成功。卸载删除私有存档，当前没有云同步或导入导出。

## 美术与音效

`WorldView` 的 sprite/enemy/dungeon 负责程序绘制的占位图形、地面、阴影和暖色光晕。替换素材时建议：图集预加载、按帧缓存、按 y 轴排序、保持碰撞体与可见体分离。不要在 onDraw 中读取文件。当前不是完整的商业像素美术资源包。

六种短 WAV 音效为原创程序合成，通过 SoundPool 播放；近战命中声音有最小触发间隔，避免敌群命中叠加过响。背景音乐、专业音效、美术动画可后续补充。外部素材需核对许可并记录第三方说明。

## 构建和发布

`demo` 用于动作版开发，`main` 保留旧版。CI 执行 Java 回归、Android lint、APK 构建与 API29 模拟器交互 smoke。新增复杂 UI 后应补实际交互验证。模拟器通过不能替代真机触控手感、帧率、发热和蓝牙音频延迟测试。

复制到新项目后修改 applicationId、namespace、Java 包名、应用名称、图标、存档格式标识和说明文档。正式发布前使用固定 release 签名并备份密钥；不要提交密钥、密码或本机 SDK 路径。依靠同一 applicationId 和签名实现保留存档的覆盖更新。

## 角色与技能扩展（0.3.0）

见 [角色配置与天赋指南](CHARACTER_BUILDS.md)。技能树定义集中在 `BuildSystem.NODES`，所有效果在纯Java核心中；UI只展示状态并调用受校验的学习/重置接口。自定义角色编辑采用副本确认提交，不能在战斗中改变构筑。存档v2显式迁移v1，新增或重排节点必须有迁移。
