# 进一步开发指南

## 1. 先复制项目并建立自己的身份

- 修改 `app/build.gradle` 中的 `applicationId`、`namespace`，以及 Java 包声明和目录。默认 `io.wayfarer.rpg` 仅供这个模板使用。
- 修改 `res/values/strings.xml` 的应用名、`res/drawable/ic_launcher.xml` 的图标。
- 修改 README、项目名和许可证版权持有人。不要将个人 keystore、密码、本机 SDK 路径提交。
- `main` 保存稳定版本，后续试验可建立 `demo`。本模板的 CI 支持这两个分支和 PR。

## 2. 内容与规则的边界

`GameData` 为只读内容定义；`GameEngine` 为纯 Java 游戏规则与状态；`MainActivity`/`WorldView` 为显示和输入；`SaveStore` 只负责磁盘写入。新增玩法优先写在核心层，界面只发命令，便于脱离 Android 运行测试。

此模板选择简单的 Java 定义表，能被编译器和 `GameData.validate()` 检查。若改为 JSON、CSV 等外部数据，请先实现严格加载和引用校验，失败时拒绝启动内容包，不要直接信任资源中的任意类名或脚本。

## 3. 新增地图

在 `GameData.AREAS` 初始化中加入 `Area`，每一行的字符数必须一致：

| 符号 | 含义 |
| --- | --- |
| `#` | 墙/树，不可通行 |
| `~` | 水，不可通行 |
| `.` | 普通地面 |
| `,` | 道路 |

坐标从左上角 `(0,0)` 开始，x 向右、y 向下。事件单独以 `Event(id, kind, x, y, target)` 定义，不能重叠。支持 `elder`、`shop`、`inn`、`enemy`、`chest`、`portal`。敌人的 target 为敌人 ID；传送点为 `目标地图ID:x:y`。

传送目的地必须可走；通常选择门口相邻空地。地图尺寸目前用宽度决定显示缩放，大地图应先加摄像机和视口裁剪。加新地图后，在测试中确认传送闭环、NPC 可接近、任务地点可到达。

## 4. 新增敌人和技能

在 `ENEMIES` 增加 `Enemy(id, name, hp, attack, defense, xp, gold)`，并添加相应地图事件。普通敌人会在旅店休息后刷新，当前首领通过 `warden` ID 特判；新增多个首领时，应改成显式的 `boss` 属性与独立完成标记，统一调整休息、逃跑、任务和存档校验。

在 `GameEngine.act()` 增加技能规则，检查资源后扣除，再计算伤害与回击。每次有效操作至多推进一次敌方回合。无效操作不能消耗资源。`MainActivity.makeActions()` 加按钮，更新帮助文本和回归测试。当前随机数用于普攻小幅浮动和逃跑，存档不保留随机序列；读档后随机结果可能改变。

## 5. 新增任务、对话和物品

当前 `quest=0..3` 表示未接取、林地委托、遗迹委托、全部完成。示例为固定线性流程，长老对话由 `interact()` 驱动。扩展多个独立任务时，改用 `Map<任务ID, 任务状态>`，将任务前置条件、奖励和一次性完成标记分别存储。

奖励必须在原子状态操作中同时更新领取标记，不能因为重开对话重复发放。普通敌人击杀数为累计值，可在接任务前累计；休息不会清零。若需要“接取后才开始计数”，请改成任务专用计数器并更新测试。

当前背包是生命/法力药水两种数量，装备是木剑→铁剑、布衣→皮甲两个永久升级。增加通用背包应使用稳定物品 ID 和数量上限，装备槽要引用背包中的合法物品；购买前先检查金币、容量和可装备性。不要只加一个界面条目却遗漏存档字段。

## 6. 替换美术和添加音效

在 `WorldView` 中将角色、事件和地形的绘图替换为资源图片；缩放图像可缓存，避免在 `onDraw()` 中读文件或分配大量位图。保持坐标变换与地图逻辑分离。现有程序图形均为原创占位图。

添加音乐建议通过生命周期管理的播放器；短音效可集中管理。切到后台应暂停/按设置继续，关闭 Activity 时释放。外来美术、音乐和字体要核对许可证并更新 THIRD_PARTY_NOTICES；不要把未经授权的素材放入仓库。

## 7. 存档兼容

`SAVE_VERSION=1` 的 Properties 存档含地图位置、属性、背包、任务、已清除事件、进行中的战斗。版本不识别、缺字段、超范围、墙内位置、无效引用、任务矛盾等会被拒绝。不会自动重置用户旧存档。

- 不要改已发布地图/事件/敌人的 ID，除非同时写迁移映射。
- 增加字段或改变字段语义时升版本，并单独实现 v1→v2 迁移，迁移后仍需完整校验。
- 读取到新对象，全部验证成功后才替换正在玩的对象。
- 保留自动存档和手动槽分离；新游戏不得删除手动槽。
- 私有本地存档不是防作弊机制。若未来做联机，服务器必须验证关键状态。

## 8. 发布自己的 APK

CI 当前输出 debug APK，不是商店正式包。稳定发布时在你自己的安全环境生成并备份 release keystore，使用 GitHub Secrets 或本地安全配置签名，绝不写入代码、日志或提交记录。每次更新递增 versionCode，保持同一个 applicationId 和签名才能保留已安装用户的存档。正式发布前进行真机操作、横竖屏、大字体、后台恢复和存储不足测试。
